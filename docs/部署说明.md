# 部署说明

## 前置条件

- Linux 与 Subversion/`svnserve`
- 所有 SVN 仓库位于同一个父目录
- 所有仓库共用同一组 `passwd`、`authz`
- 服务账号可以读取仓库，并读写认证文件和备份目录

## Windows 开发与测试

Windows 可用于运行、接口测试和界面测试，但正式 SVN 仓库仍建议只由 Linux 上的 `svnserve` 管理。

```powershell
make dev-windows
```

默认读取 `etc/config.windows.toml` 和项目内的相对路径。如果已有 Linux 配置，可在配置末尾添加：

```toml
[PathMap]
"/data/svn" = "D:/data/svn"
"/var/lib/svnpanel" = "D:/svnpanel-data"
```

`PathMap` 使用最长前缀匹配，作用于 `RepoRoot`、`PasswdFile`、`AuthzFile`、审计目录和备份目录。Windows 下建议使用 `D:/...` 形式的路径；不要直接把 Linux 的 `/data/...` 当成 Windows 路径使用。

构建 Windows 测试二进制：

```powershell
make build-windows
```

## 安装

```bash
useradd --system --home /srv/svn --shell /usr/sbin/nologin svn
install -d -o svn -g svn -m 0750 /opt/svnpanel /srv/svn/repos /srv/svn/etc /var/lib/svnpanel
install -d -o svn -g svn -m 0750 /etc/svnpanel
install -o svn -g svn -m 0600 etc/config.production.toml.example /etc/svnpanel/config.toml
install -o svn -g svn -m 0755 bin/svnpanel /opt/svnpanel/bin/svnpanel
```

编辑 `/etc/svnpanel/config.toml`，设置管理员密码、仓库路径和认证文件路径。然后：

`SVN.SvnservePath` 和 `SVN.SvnservePort` 用于“SVN 服务”页面的版本与端口状态检查。省略时默认使用 PATH 中的 `svnserve` 和 `3690`。

```bash
chown svn:svn /srv/svn/etc/passwd /srv/svn/etc/authz
chmod 600 /srv/svn/etc/passwd /srv/svn/etc/authz
install -m 0644 deploy/svnpanel.service /etc/systemd/system/svnpanel.service
systemctl daemon-reload
systemctl enable --now svnpanel
journalctl -u svnpanel -f
```

## Nginx

将 `deploy/nginx.conf.example` 的域名和证书路径改为实际值，放入 Nginx 配置目录并重载。面板默认只监听 `127.0.0.1:8080`，不要直接对外开放。

## 验证

```bash
curl http://127.0.0.1:8080/api/v1/healthz
```

浏览器访问 HTTPS 域名，使用配置中的唯一管理员登录。先新增测试用户和测试分组，在测试仓库路径授权，再用 SVN 客户端验证检出和提交。

## 故障排查

- 启动提示文件权限过宽：对配置、`passwd`、`authz` 执行 `chmod 600`。
- 看不到仓库：确认仓库是 `RepoRoot` 的直属目录，且服务账号可执行 `svnlook youngest <repo>`。
- 409 冲突：文件被其他编辑器或其他浏览器修改，刷新页面后重试。
- 422 歧义：目标 section 或身份重复，先人工检查 `authz`。
- 审计失败：检查 `/var/lib/svnpanel/audit` 的属主与写权限；审计不可写时密码查看和配置变更会被拒绝。
