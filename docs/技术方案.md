# 技术方案

## 目录

```text
main.go                 进程入口与优雅退出
etc/                    TOML 配置和开发认证文件
internal/app/          初始化、路由和 HTTP handler
internal/service/      业务编排、会话、限流和审计
internal/svncfg/       passwd/authz 解析、精准编辑、仓库扫描
internal/audit/        永久 JSONL 审计
internal/dto/          API 数据结构
pkg/                   HTTP、响应、版本等通用组件
web/                   开发磁盘资源与生产 go:embed
frontend/              Vue 3 + Vite+ 前端
deploy/                systemd 与 Nginx 示例
docs/                  需求、技术和部署文档
```

后端采用 router → service → file adapter。`internal/svncfg` 是本项目的文件持久化层，替代数据库 DAL 和 ORM。

## 配置编辑

- 文件以 UTF-8 读取并保存 BOM 或原始行结束符。
- 编辑只替换目标用户名、成员值或 ACL 权限值对应的文本区间。
- 插入新行时使用文件主流行结束符。
- 每个写请求必须携带 `passwd`、`authz` 的 SHA-256 revision。
- 写入由进程互斥锁和跨进程文件锁串行化。
- 发布前备份两份文件，临时文件 `fsync` 后原子替换。
- 发布后审计失败时使用备份回滚。

## ACL

- section：`[repo:/path]`
- 身份：用户、`@group`、`*`、`$authenticated`、`$anonymous`
- 权限：`r`、`rw`、空值
- 有效权限首先定位最近且包含匹配规则的路径，再合并用户、分组和内置身份权限。
- 遇到 aliases、嵌套分组、反转规则或未知权限时，预览明确标记为不完整。

## 备注和部门

- 用户备注写入 `passwd` 条目正上方的 `# svnpanel:remark:`。
- 部门定义写入共享 `passwd` 的 `# svnpanel:departments:` 全局注释。
- 用户固定部门写入 `# svnpanel:department:`，取值来自 `passwd` 中的部门定义。
- SVN 分组备注写入 `authz [groups]` 分组行正上方。
- 元数据必须与目标条目相邻，其他人工注释不参与关联。
- 用户或分组删除时，面板同步删除紧邻元数据。
- 不同步到辅助数据文件，也不参与 SVN 权限计算。

## 安全

- 只有 `/api/v1/auth/login` 与 `/healthz` 无需认证。
- Cookie 使用 HttpOnly、Secure、SameSite=Strict。
- 所有写请求必须提供会话 CSRF Token。
- 登录失败有 5 次限流；密码查看仍要求有效登录会话和 CSRF Token。
- 生产监听 `127.0.0.1`，由 Nginx 终止 TLS。

## 接口补充

- `GET /api/v1/svnserve` 只读返回 svnserve 版本、端口连通性、认证文件及仓库 revision。
- `PUT /api/v1/users/:name/metadata` 更新用户备注和固定部门。
- `POST /api/v1/users/batch` 原子执行批量启用、停用、重置密码或设置部门。
- `POST /api/v1/departments` 添加部门定义。
- `PUT /api/v1/departments/:name` 重命名部门，并同步更新用户引用。
- `DELETE /api/v1/departments/:name` 删除未被用户使用的部门。
- `GET /api/v1/files` 读取 `passwd`、`authz` 原生内容和 revision。
- `PUT /api/v1/files/:name` 校验完整配置后原子替换指定原生文件。
- `GET /api/v1/snapshots` 读取最近配置快照列表。
- `GET /api/v1/snapshots/:id` 读取快照中的 `passwd`、`authz`。
- `POST /api/v1/snapshots/:id/restore` 整组恢复快照，并在恢复前备份当前状态。
- `PUT /api/v1/groups/:name/permissions` 一次性替换分组在各仓库路径上的显式 ACL。
- 创建用户可同时提交备注、固定部门和目标 SVN 分组，用户与分组在同一事务中写入。
- 新增用户页使用浏览器安全随机数生成 16 位 `[A-Za-z0-9]` 密码。
- 所有写入仍要求 `passwd`、`authz` revision，并统一经过备份、原子替换和审计流程。

## 原生文件编辑器

- 前端使用 Monaco Editor 0.58.0，仅按需加载编辑器核心和必要的查找、折叠、注释等 contribution，不加载全部内置语言。
- `svnconfig` 自定义 Monarch 语法高亮覆盖注释、section、用户/分组键、`@group`、`$authenticated`、`$anonymous` 和读写权限。
- 页面路由懒加载，编辑器 worker 独立分包，不增加登录页和用户列表首屏体积。
- 历史快照使用 Monaco Diff Editor 对比快照与当前草稿，恢复仍执行 revision 冲突检查和审计。

## SVN 服务状态

- `SVN.SvnservePath` 和 `SVN.SvnservePort` 指定服务端可执行文件与待检查端口，默认分别为 `svnserve` 和 `3690`。
- `SVN.SvnserveConfigFile` 指定只读展示的 `svnserve.conf`；省略时默认使用 `PasswdFile` 同目录下的 `svnserve.conf`。
- 服务页解析 `[general]` 中的 `password-db`、`authz-db`、`realm` 和访问策略，并与面板实际使用的认证文件比较；配置文件不在页面中编辑。
- 版本通过 `svnserve --version` 实时读取，服务状态通过本机 TCP 端口连通性判断。
- 仓库列表和 revision 复用 `svnlook youngest` 扫描，不修改或控制 svnserve 进程。
